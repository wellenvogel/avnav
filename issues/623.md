# Issue 623 - send the active leg to the SignalK v2 `navigation.course.*` paths

## Problem
`server/handler/signalkhandler.py` (sendWp) only sent the active leg to the v1 paths
`navigation.courseGreatCircle.*` / `courseRhumbline.*`. signalk-to-nmea2000 needs the v2 paths
`navigation.course.*` to create PGN 129283/129284, so an autopilot got no NAV data.
Main use case: correct NMEA0183/NMEA2000 data for an autopilot.

## Decision (final, simple approach)
- Send **deltas only** on the v2 paths (no REST sync of the course, no `PUT destination`).
- AvNav's active leg must win: if SignalK holds a course not coming from us, reset it via REST first.
- The SignalK `course-provider` plugin cannot interwork nicely -> the user has to **disable the plugin**
  when AvNav sends the waypoint. AvNav only detects a running plugin and shows an error.

## Implemented (unstaged, `server/handler/signalkhandler.py`)
- Param `legPaths` (`v1`/`v2`/`both`, default `both`, condition sendWp).
- `getLegDataV1()` (original data), `getLegDataV2()`:
  `navigation.course.nextPoint`, `previousPoint` (`{position,type:'Location'}`, previousPoint = leg start),
  `arrivalCircle`, and `calcValues.(calcMethod,distance,bearingTrue,bearingTrackTrue,crossTrackError,velocityMadeGood)`
  only if `not providerActive`. `getLegData(wpData,v1,v2)`, `useCourseV2()` = `legPaths != 'v1' and skVersionOk`.
- v2 only if the server is >= 2.0 (`skVersionOk = hasNotifications`).
- `checkCourse()` (timer 10s): version check, then `checkCourseProvider()`:
  reads `/skServer/plugins/course-provider/config` (404 -> none; 401/403 -> `_probeProvider` on
  `/signalk/v2/api/vessels/self/navigation/course/calcValues`, 200/400 = running).
  Status entry `courseProvider`: green = no/disabled plugin (we send calcValues), red = plugin running
  ("please disable it", no calcValues sent), grey = v2 disabled / check failed (last state kept).
- `resetForeignCourse()` (max every 10s, only if leg valid and v2 used): `_foreignCourse()` reads v1 model
  `.../navigation/course/nextPoint`; if `$source` is not ours (`isOwnSource`, `avnav-<uuid>`) ->
  `DELETE /signalk/v2/api/vessels/self/navigation/course` via `NotificationV2Handler` (needs write permission).
- The off requests for the unused routing mode only use v1 (`v2=False`).
- Removed: `courseProvider` param (never/auto/force), REST sync (`syncCourseApi`), `courseApi` status.
- Doc updated: `newDoc/docs/de/special/signalk.md` (legPaths row, v2 mapping paragraph, plugin-disable hint,
  reset behaviour). Not yet translated to other languages.

## Findings about SignalK (2.33.0, localhost:3000, admin/signalk)
- `navigation.course.*` deltas are stored in the delta model (`/signalk/v1/api/vessels/self/navigation/course`)
  with `$source=avnav-<uuid>` and are consumed by course-provider and signalk-to-nmea2000.
- The v2 course API (`GET /signalk/v2/api/vessels/self/navigation/course`) keeps its own state and does
  NOT show our deltas (stays null); it adopts v1 `courseGreatCircle` only from NMEA-typed sources.
- `PUT .../course/destination` needs `navigation.position` (else 400 "Unable to retrieve vessel position")
  and always sets previousPoint to the vessel position.
- course-provider (SignalK/course-provider-plugin, `src/index.ts`) subscribes to `navigation.course.*`
  but only calculates on a `navigation.position` delta; without a position it skips (no calcValues).
  It also overwrites calcValues, so it cannot be mixed with our calcValues. Switching its calc mode
  or coordinating with it was tried and dropped as too fragile.
- `DELETE` of the course with a token works.
