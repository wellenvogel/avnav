# Connections

To allow AvNav to process data from instruments, connections to onboard networks can be established. An introduction to this can be found under [Data Flow](../base/dataflow.md).

This chapter describes some further details.

## Structure {: #structure}

As briefly described in the [Introduction](../concept/clientserver.md), AvNav consists of a server part, which processes and stores navigation data and charts, and a display part (client), which runs in a browser. The connections to the onboard networks are established in the server part.

![Server Structure](../../img/server-structure.png)
///caption
Server Structure
///

The image shows a rough structure of the components that make up the server software. To understand the connections, the "NMEA Multiplexer" is particularly important. This receives and distributes NMEA0183 data from and to various inputs and outputs. This distribution takes place regardless of whether AvNav itself can do anything with this data.

This multiplexer works together with the "AvNav Core" - the part that decodes and stores NMEA data, and performs routing functions and other navigation functions.

The multiplexer offers a number of filter functions.

To make data from the onboard networks available in AvNav or to feed data generated by AvNav into them, connections must be configured (marked in red in the image above).

AvNav itself can only process NMEA0183 data. For connections to NMEA2000 bus systems, you can find further information under [NMEA2000](nmea2000.md).

Special notes on working with SignalK can be found in a [separate description](signalk.md).

## Connections Page {: #channelspage}

The configuration of connections in AvNav is done via

{{MM("MMchannelspage")}}

![Connections Page](../../img/channelspage.png)
///caption
Connections Page
///

On this page, you can see all already configured connections, edit them, delete them, and add new connections.

The designations of the connections differ slightly between Android and Linux/Windows, but the functions are largely identical.

In addition to the connection-specific parameters such as the port for a TCP connection, you can also define a number of parameters that influence how the data is handled. This particularly concerns the filter functions that the multiplexer possesses.

| Parameter | Description |
| --- | --- 
| name | A name for this connection. This name can be used if you do not want to output the data received via this connection on certain connections (blacklist) |
| filter, readFilter | A filter that only allows certain messages through. See [Filter](configfile.md#filter)|
| priority | If, for example, position data is received via multiple connections, the values would overwrite each other in AvNav's internal data storage. If these differ, this leads to jumps in the display. With the priority, you can control which data wins in each case (higher priority). Only when no such data has been received for some time are data with lower priority used. However, the multiplexer forwards the data in any case. |

## Connection Types

In the following table, you can click on the type name to get to the description of the configurable parameters.
Note: In some places under Linux/Windows, the names have a prefixed "AVN" - this is omitted in the table.

| Name Linux/Windows| Name Android | Description |
| --- | --- | --- |
| [USBSerialReader](configfile.md#avnusbserialreader) | --- | Linux only. Management of detected USB devices with a serial profile. AvNav detects such devices automatically and configures them for data reception with automatic baud rate detection. You can also specify special parameters for individual devices |
| --- | [UsbConnection](configfile.md#usbconnection) | Android only. When a USB device with a serial profile is connected, AvNav offers to use it. For this, permissions must be granted. Subsequently, the device can be configured in AvNav and used as an input or output |
| [BluetoothReader](configfile.md#avnbluetoothreader)| [Bluetooth](configfile.md#bluetooth)| Linux: Similar to USB devices, Bluetooth devices with a serial profile are detected and configured for data reception.<br>Android: If a Bluetooth device is to be used, it must first be "paired". After that, a connection to such a device can be created |
| [SocketWriter](configfile.md#avnsocketwriter)|[TcpWriter](configfile.md#tcpwriter)| A TCP server is configured. The port on which AvNav should accept connections must be specified. In addition, you can choose whether access should only be possible locally or also from other computers (Android: `externalAccess`, Linux/Windows: `host 0.0.0.0`). Sending and receiving is possible - the default entry is: `send`.|
| [SocketReader](configfile.md#avnsocketreader) | [TcpReader](configfile.md#tcpreader) | A TCP client connection is configured to another system that is configured as a server. The IP address and port must be specified. Instead of the IP address, a host name can also be specified. In particular, a name of the form `name.local` - i.e., an mDNS address - can be used. Data can be received and sent. The default entry is: `receive`|
| [Nmea0183ServiceReader](configfile.md#avnnmea0183servicereader) | [NMEA0183 service](configfile.md#nmea0183service)| The same function as a SocketReader. Instead of an IP address and port, however, the name of a Bonjour service is specified (selection from a list). The advantage of this configuration is that the connections are automatically re-established, even if, for example, the Wi-Fi network being used changes. |
| [UdpReader](configfile.md#avnudpreader)|[UdpReader](configfile.md#udpreader)| AvNav opens a UDP socket and receives messages. It can be decided whether only messages from your own computer or also from other computers are received. (Android: `externalAccess`, Linux/Windows: `host 0.0.0.0`) |
| [UdpWriter](configfile.md#avnudpwriter) | [UdpWriter](configfile.md#udpwriter)| AvNav sends UDP messages to another system. IP address and port must be specified.|
| [SignalKhandler](configfile.md#avnsignalkhandler)| --- | A special connection to [SignalK](signalk.md). The data received from there does **not** go into the multiplexer, but only into the internal data storage|

## Sensor Connections

Under Linux on the [AvNav Images](../installation/raspberry.md#images), some I2C sensors can also be configured.
These feed specific NMEA telegrams into the multiplexer.
See the description of the respective configuration for this.

* [BME280](configfile.md#avnbme280reader)
* [BMP180](configfile.md#avnbmb180reader)
* [SenseHat](configfile.md#avnsensehatreader)
